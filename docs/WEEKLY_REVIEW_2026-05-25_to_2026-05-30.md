## 4. Key Problems Found

### Problem A: `direction_trend` is still too tied to day change

Evidence:

- 2026-05-26 wave 2: RKLB fell -3.58%, but system gave three wrong-side `direction_trend/long/STRONG`.
- 2026-05-27 wave 4: RKLB fell -3.30%, system gave `direction_trend/long/STRONG conf=95`.
- 2026-05-28 wave 12: RKLB fell -3.62%, system gave five wrong-side STRONG long signals.
- 2026-05-28 wave 17: RKLB fell -3.39%, system gave two wrong-side STRONG long signals.

Root cause:

- `direction_trend` treats large positive day change as strong bullish context.
- It does not sufficiently respect local rollover structure: lower highs, falling 10-15m momentum, failed VWAP, or top exhaustion.

Optimization proposal:

- Do not silence `direction_trend`.
- Cap its confidence when local structure disagrees:
  - day change still strongly positive, but
  - price is below VWAP, or
  - 10/15m momentum is flat/down, or
  - recent 5m highs are lower-highs, or
  - price has rolled over from session high.
- Result should be:
  - from `STRONG 80-95` -> `WEAK/一般 55-65`
  - text: "大涨背景仍在，但短线结构转弱，暂不追多"

This preserves directional context but stops the system from shouting "strong long" into a rollover.

### Problem B: Early-session large waves are still missed

Evidence:

- 2026-05-28 first four waves were MISS:
  - DOWN -6.11%
  - DOWN -3.27%
  - UP +3.08%
  - DOWN -5.82%
- 2026-05-29 first two UP waves were MISS.
- 2026-05-30 first four waves were MISS, including alternating 2%-3% moves around the open.

Root cause:

- The system is cautious around volatile opens.
- 5m trigger cadence is not enough for 5-20 minute fast waves.
- `near_support` / `crash_rebound_watch` often arrives after the first tradable rebound leg has already started.

Optimization proposal:

- Add a **replay-only open volatility detector** first, not live.
- Use 1m + 5m review data to label:
  - first 60 minutes after RTH open
  - fast flush >2%
  - reclaim from local low >0.8%-1.2%
  - VWAP / 1m MA5 / 5m MA5 confirmation
- It should initially log shadow signals only:
  - `open_flush_watch`
  - `open_reclaim_watch`
  - `open_breakdown_watch`
- Promote only after replay proves it reduces MISS without increasing wrong STRONG.

### Problem C: `crash_rebound_watch` improves rebound coverage, but enters late

Evidence:

- 2026-05-30 wave 6: UP +6.75%, first relevant signal arrived 22 minutes after wave start.
- 2026-05-30 wave 8: UP +4.43%, first relevant signal arrived 3 minutes after wave start, good.
- 2026-05-29 rebound wave: several long watches came after the low was already behind.

Root cause:

- Current rebound detector waits for confirmation, which avoids some false positives but sacrifices entry timeliness.

Optimization proposal:

- Keep current confirmed `crash_rebound_watch` as the safer signal.
- Add a pre-confirmation shadow layer:
  - local low formed
  - 1m bounce begins
  - sell volume weakens
  - price reclaims 1m MA5 or short VWAP
- Text should say "反弹观察提前版", not "买入".
- Only promote if forward cases show useful favorable move after alert.

### Problem D: Position followup became active but too noisy

Evidence:

- 2026-05-29:
  - `position_followup`: 31
  - `stop_loss_warning`: 26
  - strong count inflated to 62 mostly because risk/followup uses STRONG labels.
- 2026-05-29 followup states:
  - `INVALIDATED`: 28
  - `COST_RETEST`: 1

Root cause:

- Followup successfully catches invalidation, but it still looks like repeated alarm noise.
- It does not yet clearly separate "direction invalidated once" from repeated stop-loss reminders.

Optimization proposal:

- Make followup state machine single-source-of-truth while holding:
  - `HOLD_OK`
  - `TOP_WATCH`
  - `COST_RETEST`
  - `INVALIDATED`
  - `DATA_UNTRUSTED`
- During a held position, suppress independent:
  - repeated `stop_loss_warning`
  - repeated drawdown warnings
  - profit target noise
- Allow only one `INVALIDATED` per position unless a new level breaks.

## 6. Recommended Optimization Plan

### P0: Fix measurement and review quality

1. Ensure runtime error `DataFrame truth value ambiguous` is gone.
2. Ensure daily review uses 1m archive when available.
3. Add weekly aggregate report:
   - total waves
   - TIMELY/LATE/MISS/WRONG_SIDE
   - wrong STRONG
   - top false-positive trigger
   - top missed-wave time window

### P1: Confidence honesty for `direction_trend`

Implement only after replay:

- If `direction_trend/long/STRONG` but local structure is rolling over, cap to 55-65.
- Do not silence it.
- Do not change direction.
- Keep text explicit: "日内仍强，但短线结构转弱，信心封顶".

Replay requirement:

- Must reduce 2026-05-26/27/28 wrong STRONG count.
- Must not increase 2026-05-29/30 MISS count.

### P2: Fast-wave shadow detector

Start as logging only:

- `open_flush_watch`
- `open_reclaim_watch`
- `open_breakdown_watch`

Use:

- 1m price structure
- 5m confirmation
- VWAP/MA reclaim
- local high/low break

Promotion requirement:

- Improves first-signal latency on 05-28/05-29/05-30.
- Does not add wrong STRONG.

### P3: Position followup cleanup

Goal:

- Fewer repeated alarms.
- More useful state transitions.

Rules:

- One `INVALIDATED` per position/level.
- `COST_RETEST` only once per position unless new high/low changes context.
- Independent stop/profit warnings are suppressed while followup owns the position.

## 7. What Not To Do

- Do not loosen all direction guards just because signals were quiet.
- Do not promote VectorBT/Optuna templates yet.
- Do not optimize based on one screenshot or one trade.
- Do not make `direction_trend` louder.
- Do not turn shadow wave candidates into Telegram alerts before forward-case validation.

## 8. Bottom Line

The live strategy improved after data quality fixes, but last week shows the next bottleneck:

- **Wrong confidence:** trend labels sometimes stay too confident after rollover.
- **Late/missed fast waves:** open and rebound moves are not caught early enough.
- **Followup noise:** invalidation is detected, but repeated risk messages still need consolidation.

The safest next step is not a large strategy rewrite. It is:

1. cap overconfident `direction_trend`,
2. build fast-wave detectors in shadow mode,
3. clean position followup,
4. require replay before promotion.
